\section{Depth Beats Breadth}
\label{sec:depth-vs-breadth}
% -----------------------------------------------------------

% TODO [~250 w] THIS IS THE STANDOUT FINDING.
%
% ¶1 Set up the comparison:
%   run_02 (100 patients * 50 epochs) outperforms run_03
%   (3,300 patients * 5 epochs) in best-val PSNR by [X dB],
%   despite run_03 seeing 33x more unique images. Episodes-per-
%   image, not raw data volume, drives convergence.
%
% ¶2 Mechanism:
%   The pi_2 head benefits from repeatedly seeing the same image
%   under different (sigma, mu) trajectories -- it needs to
%   integrate gradients across many episodes per state to
%   converge. Spreading the training budget across more images
%   gives each image fewer episodes, the critic baseline is
%   noisier, and pi_2 fails to stabilise.
%
% ¶3 Connection to the paper:
%   The TFPnP paper trained on 17,125 PASCAL VOC images for
%   2,500 iterations. The total budget is large; the per-image
%   depth depends on batch size and dataset size and is not
%   directly reported. Our finding suggests this "per-image
%   depth" is the load-bearing axis and should be reported
%   explicitly in future replications.
%
% ¶4 (Optional) Caveat:
%   We have not separated the two effects (lower data variety vs
%   more updates per image) by running a controlled experiment
%   at fixed total batches with different patient counts. Stated
%   as a limitation -- but the qualitative finding is robust to
%   that ambiguity because run_03 had both more images AND fewer
%   updates per image.
%

\section{DRUNet Over-Smoothing}
\label{sec:drunet-oversmoothing}
% -----------------------------------------------------------

% TODO [~200 w]
% ¶1 Observation:
%   Qualitative reconstructions (Fig 5.5) show TFPnP outputs are
%   smoother than ground truth, particularly in lung textures
%   (fine vasculature, bronchial walls). HaarPSI gains lag PSNR
%   gains, consistent with residual texture loss.
%
% ¶2 Diagnosis:
%   DRUNet is trained on BSD400 natural images. Lung CT texture
%   is structurally different (fine, low-contrast, noise-like
%   patterns) and DRUNet treats it as noise to be removed. This
%   is NOT a TFPnP failure mode -- it is a denoiser-domain
%   mismatch. The RL policy cannot recover detail the denoiser
%   has removed.
%
% ¶3 Framing as positive:
%   That TFPnP still achieves competitive PSNR with this denoiser
%   limitation supports the paper's modularity argument. Future
%   work could fine-tune DRUNet on CT, or swap to a CT-specific
%   denoiser, with no change to the policy or environment. This
%   is the modular generalisation argument made concrete.
